# 2026-09-28 코어 검증 기록

실행한 환경은 macOS arm64, Apple clang 21이다. terminal source는 tmux `94796f6b1182507efac8a272fc309a79e22e58a5`다. masil과 stock baseline을 동일한 `-O2`, utf8proc, jemalloc 설정으로 빌드했다. 실제 compile에는 `-Werror`를 적용했다. upstream macOS 설정과 같은 compatibility-header warning 예외를 두었고 configure의 기능 탐색에는 `-Werror`를 적용하지 않았다. [masil build](data/core-build.json), [baseline build](data/baseline-build.json)에 hash와 flag가 있다.

## native 호환 검증

[tests/test_compatibility.py](../../tests/test_compatibility.py)는 같은 초기 설정에서 masil과 baseline을 비교한다.

- `list-commands`의 등록 명령 92개, `list-keys`, server/session/window 옵션 dump의 동등성.
- EDITOR에 따른 vi/emacs 기본값과 Unicode buffer/format/capture/copy mode.
- session·linked window·split·tiled layout·zoom·unlink의 상태.
- 실제 PTY client에서 `C-b c`, `C-b d` 및 detach 뒤 server/session 생존.
- control mode의 `%begin/%end`와 알림/응답 경계.
- native 오류·alias·hook·비동기 command queue.
- masil에서 stock으로, stock에서 masil로 보낸 `kill-server`의 protocol 거절과 대상 생존. 같은 masil의 `TMUX` 상속은 정상 접속.

기본 키를 바꾸거나 masil용 binding을 추가하지 않았다. 이 commit의 빌드는 `TMUX_MOUSE=1`이므로 기본 mouse는 on이다. 과거 문서에 적었던 소스 fallback 값 off를 실제 build 기준으로 정정했다.

`-V`를 `masil ...`로 바꾸면 upstream version format 테스트와 기존 script의 `sed 's/^tmux //'` 파싱이 깨졌다. 제품 executable 이름은 masil로 두고 version 출력은 upstream 문자열로 복원했다. native protocol은 8-bit 비교를 하므로 그 범위를 벗어나는 제품 magic 대신 136을 쓴다.

## 관찰과 실패 경로

[tests/test_bridge.py](../../tests/test_bridge.py)는 private socket에서 hello·inventory·snapshot·stats, 중복/미지원 field, malformed/oversize frame, snapshot clipping, 잘못된 generation, 삭제된 pane, rate limit을 확인한다. application base screen과 copy mode overlay를 구분하며 출력·resize·reset·respawn·종료 뒤 이전 snapshot의 유효성이 바뀌는지 검사한다.

독립 코어 검토가 발견한 두 문제를 수정했다.

1. 출력 없는 child 종료 뒤 remain-on-exit banner와 cursor 변경이 screen generation에 반영되지 않았다. 화면을 바꾼 뒤 generation을 증가시키고 조용한 종료 fixture로 재현·검증했다.
2. destructive respawn의 forkpty 실패 시 기존 PTY가 사라졌어도 generation이 유지됐다. 기존 PTY를 닫기 전에 generation을 바꾸고 정상 성공 경로의 중복 증가를 제거했다.

[tests/test_respawn_failure.py](../../tests/test_respawn_failure.py)는 test-only dylib을 private masil server에만 주입하여 forkpty가 EAGAIN으로 실패하게 한다. 이전 PTY/screen fence의 거절과 이후 성공한 respawn의 단일 증가를 확인한다. production binary에 interposer를 연결하지 않고 사용자 process limit도 변경하지 않는다. 수정 후 독립 검토에서 두 항목의 해결을 확인했다.

## upstream suite의 원시 결과와 재검증

[전체 실행 결과](data/upstream-faa3788fa9e7.json)는 각 제품의 164개 script를 실행한 기록이다. 최초 유효 전체 실행은 stock 162/164, masil 160/164였다. 실패 항목을 다음과 같이 처리했다.

| script | 최초 | 처리와 재검증 |
| --- | --- | --- |
| `format-variables.sh` | masil 실패 | `-V`의 upstream 문자열 복원. [두 제품 재검증 통과](data/upstream-9a4ce13f5e43.json) |
| `socket-path.sh` | masil 실패 | 의도한 `masil-UID` namespace를 temporary test copy의 기대값에만 반영. [통과](data/upstream-2b08eb4b7539.json) |
| `terminal-feature-utf8.sh` | 둘 다 실패 | nested `env -i`가 private `TMUX_TMPDIR`까지 제거해 다른 socket을 찾았다. private 경로만 보존하며 locale 제거 조건은 유지. [통과](data/upstream-b0af63c9073d.json) |
| `screen-redraw-menus.sh` | 둘 다 실패 | `menu-over-split` 화면이 golden fixture와 다름. 공통 미해결 실패로 유지 |

메뉴 테스트의 실제 오류는 두 제품에서 같다.

```text
scene menu-over-split differs from screen-redraw-results/menu-over-split.result
```

[masil 로그](data/masil-screen-redraw-menus.log), [stock 로그](data/tmux-baseline-screen-redraw-menus.log)를 보존했다. fixture 기대값은 변경하지 않았다. 같은 오류 메시지는 동일 원인 확정이나 해당 기능의 정상 동작 증거가 아니다.

[합산 결과](data/upstream-consolidated.json)는 최신 재검증 결과를 해당 script에 적용해 각각 163 pass / 1 fail로 기록한다. 한 번의 전체 green 실행이 아니며 run별 frozen binary hash도 남겼다. 마지막 generation 수정은 별도 통합·실패 주입 테스트로 검증했다. `scripts/test_upstream.py`를 다시 실행하면 새로운 독립 run directory에서 전체 결과를 얻는다.

초기에는 두 작업자가 같은 frozen binary 경로에서 suite를 겹쳐 실행하여 macOS에서 실행 파일이 교체되는 문제가 있었다. 그 실행은 무효로 제외했다. runner를 run별 binary/log directory로 수정한 뒤 위 전체 실행을 수행했다. 각 script는 private socket과 process group을 사용하며 종료 시 그 범위만 정리한다.

```sh
make test
python3 scripts/test_upstream.py --jobs 4 --timeout 90
```

두 번째 명령의 공통 메뉴 테스트는 현재 이 환경에서 실패할 수 있으며, runner는 실패를 성공으로 바꾸지 않는다.
