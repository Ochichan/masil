# 2026-09-28 M2 실시간 관찰 검증

기준 commit은 `4381ec2`이며, 그 위에 선택 pane의 watch stream과 Rust CLI를 구현했다. protocol·메모리 상한·현재 제공 범위는 [관찰 계약](../core-observation.md), 구현 계획과 체크리스트는 [M2 계획](../design/m2-watch-implementation.md)에 있다.

## 구현과 테스트

`make test`가 exit 0으로 끝났다. [실행 로그](data/m2-make-test.log), [코어 build](data/m2-core-build.json), [실제 소스·binary hash](data/m2-manifest.json)를 보존한다.

| 검사 | 결과 | 의미 |
| --- | --- | --- |
| 기존 native 호환 | 10/10 통과 | 명령·키·옵션·실제 PTY·control mode·socket 격리 유지 |
| 기존 bridge / forkpty 실패 주입 | 통과 | snapshot/generation 및 실패한 respawn 처리 유지 |
| 실제 코어 watch | 8/8 통과 | 아래 scope·수명·용량·slow-reader 검증 |
| Rust CLI mock stream | 통과 | 정상·malformed·gap·EOF·idle·partial timeout·BrokenPipe |
| Rust unit | 2/2 통과 | JSON 중복 key/깊이/UTF-8 검증 |
| benchmark helper | 6/6 통과 | 기존 측정 도구 검증 |

실제 코어의 [watch 테스트](../../tests/test_watch.py)는 다음 경로를 다룬다.

1. 잘못된 boot, 중복·없는 pane, 65개 scope를 원자적으로 거절한다. idle이면 event와 dirty timer가 없다.
2. 관찰하지 않은 pane의 출력은 보내지 않는다. 연속 출력은 합치고, 새 구독의 fence 이전 event를 재생하지 않는다.
3. resize·respawn·exit·remove를 전달한다. 삭제 직전 dirty가 삭제 후 stale event로 나오지 않는다.
4. 자식 process 없는 빈 pane으로 512개 slot을 채운다. 추가 대상을 거절하되 기존 pane 공유는 허용한다. 마지막 reference 해제 뒤 slot을 다시 쓸 수 있다.
5. resize 10,000개로 journal을 넘겼을 때 gap/연결 종료를 확인한다. native command가 계속 동작하며 새 watch baseline으로 복구할 수 있다.
6. 별도의 지속적인 출력원과 읽지 않는 구독자를 동시에 둔다. TX가 막힌 동안 native send-keys/capture가 진행되고, peer를 수동 종료하지 않아도 약 5초 뒤 subscription/slot이 정리된다. 이때 event 수는 4,096 미만이고 gap counter는 0이므로 journal overflow와 송신 deadline을 구분한다.
7. 다른 scope의 record 1,000개 뒤에 대상 event 하나를 넣는다. 이후 native 입력이 없어도 scan continuation이 마지막 event까지 전달한다.
8. 실제 `bin/masil-agent watch --count 1`이 실제 코어의 ACK와 event를 받고 정상 종료한다.

새 mock CLI 테스트는 [test_watch_cli.py](../../tests/test_watch_cli.py)에 있다. worker의 `cargo fmt --check`, `cargo clippy -- -D warnings`, debug/release build도 통과했다. root는 최종 release CLI로 통합 테스트를 실행했다.

## 독립 검토에서 수정한 내용

- 다른 scope의 event까지 스캔한 서버 cursor는 마지막 전달 sequence보다 클 수 있다. CLI가 정상 gap을 protocol 오류로 오인하던 비교를 수정하고 해당 mock을 추가했다.
- OS socket timeout을 올림한 뒤 마지막 byte가 늦게 도착하면 3초 frame deadline을 넘어도 수락할 수 있었다. read 직후 monotonic deadline을 다시 검사하고 지연된 마지막 byte를 검증한다.
- 최초 overflow 테스트는 부하가 끝난 뒤 native 입력을 확인했다. 지속적으로 막힌 TX와 native 입력을 동시에 실행하는 별도 테스트를 추가했다.
- dirty callback은 최대 64개 발행 외에 200µs soft quantum을 확인하고 다음 callback으로 양보한다. 개별 처리나 OS scheduling의 실시간 deadline 보장은 아니다.

수정 후 독립 집중 검토에서 세 항목의 해결과 dirty callback의 안전한 재예약을 확인했다. 남은 blocking finding은 없다.

## 관찰 기능의 추가 비용

[원시 결과](../benchmarks/data/2026-09-28-watch.json)는 같은 최종 masil binary에서 bridge off와 1개 watch 연결을 비교한다. watch-on에서는 선택 pane 전체를 구독했다. headless active 93×39 / hidden 94×39, inplace ASCII 합계 약 1 MiB/s이며 조건별 idle/output 각 5초를 한 번씩 실행했다.

서버만의 RSS와 한 logical core를 100%로 한 평균 CPU다. Python workload child, reader thread가 있는 측정 process, agentd 비용은 포함하지 않는다.

| Pane / 부하 | off RSS / CPU | watch RSS / CPU | 수신 event |
| --- | ---: | ---: | ---: |
| 1 / 대기 | 3.97 MiB / 0.00% | 4.12 MiB / 0.00% | 0 |
| 1 / 출력 | 3.97 MiB / 2.41% | 4.12 MiB / 2.40% | 21 |
| 50 / 대기 | 4.44 MiB / 0.00% | 4.55 MiB / 0.00% | 0 |
| 50 / 출력 | 4.84 MiB / 1.72% | 5.00 MiB / 3.25% | 1050 |

50-pane 대기에서 event=0, pending_dirty=0, flush_timer_active=false였다. 출력 후에도 pending dirty와 timer가 정리됐고 stream loss가 없었다. 50-pane 출력의 추가 CPU는 이 실행에서 약 1.54 percentage points였고 RSS 증가는 0.16 MiB였다. 4 Hz stream의 첫 알림과 마지막 완료 marker도 event 수에 포함된다.

5초의 짧은 샘플, 고정 실행 순서, `ps` 0.01초 CPU 분해능 때문에 작은 차이와 0.00%를 정확한 무비용으로 해석하지 않는다. `budget_eligible=false`를 유지한다. 10분 idle, 반복 출력, 여러 observer/실제 provider/다중 client까지 포함한 최종 성능 gate는 아직 실행하지 않았다.

```sh
make test
python3 tests/performance/watch_benchmark.py \
  --seconds 5 --output .build/watch-comparison.json
```

## 남은 범위

지금은 명시적으로 고른 pane의 읽기 전용 invalidation stream이다. provider adapter, agent session/binding, agentd, durable prompt/approval/복구, reconnect 과거 event replay는 제공하지 않는다. 실제로 읽은 최신 snapshot/inventory와 새 baseline이 필요하다.

이 묶음에서는 전체 upstream suite를 반복하지 않았다. 초기 코어의 메뉴 golden fixture 공통 실패 1건은 [이전 검증 기록](2026-09-28-core.md)에 남아 있다. 다른 OS·IME·clipboard·SSH·장시간 부하는 여전히 미검증이다.
