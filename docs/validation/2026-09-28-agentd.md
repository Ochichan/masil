# M3 첫 관찰 daemon 검증

2026-09-28, macOS 26.6.2 arm64. 기준 commit `ee913cc` 이후 OpenCode native session 관찰을 추가했다. 변경 범위는 Rust daemon·adapter·CLI, build 실행 검사, 테스트와 문서다. C terminal core와 tmux 기본 key table은 변경하지 않았다. [실행 안내](../agent-observation.md), [구현 계획과 범위](../design/m3-observer-implementation.md).

## 구현 결과

- `serve --core --config`로 명시적으로 시작하는 단일 thread daemon. `status`, `agents`, `inspect`, `stop` 제공.
- source당 하나의 OpenCode SSE와 HTTP client. GET snapshot에서 activity, pending permission/question, native session identity를 확인한다.
- native session 존재 미확인은 null, 연결 손실은 unknown/stale, 새 snapshot과 event가 겹치면 syncing. idle을 완료나 성공으로 바꾸지 않는다.
- 지정한 pane과 native session의 association은 `explicit_unverified`다. PTY 교체·종료·제거 또는 core 관찰 손실은 `invalidated`로 바꾸며 자동 복구하지 않는다.
- private UDS, same UID, frame·client·메모리 보관 상한, deadline, 중복 daemon lock. stop은 provider/core를 종료하지 않는다.

실제 private core와 mock OpenCode를 연결한 integration은 부모·자식 분리, 승인/질문 우선순위, idle 무재조회, read-only GET, socket mode, 중복 lock, no-autostart, graceful stop, pending ID truncation, 401·oversize·SSE EOF·malformed, 느린 source/client, PTY 교체·pane 제거·core 연결 손실을 확인했다. snapshot 도중 native event가 오거나 SSE frame이 반만 도착했을 때 기존 snapshot을 fresh로 공개하지 않는지 검사했다. 연속된 무관 SSE 이벤트 아래에서도 snapshot과 관리 조회가 진행됐다.

최종 [전체 테스트 로그](data/2026-09-28-agentd-tests.log), [clippy 로그](data/2026-09-28-agentd-clippy.log)를 보존했다. 기존 upstream 전체 164개 suite는 C 변경이 없어 이번 묶음에서 재실행하지 않았다. stock과 rmux 모두에 남았던 메뉴 golden fixture 차이는 [이전 기록](2026-09-28-core.md)의 제한으로 유지한다.

설치본 smoke는 HOME, XDG config/data/state/cache, cwd, 인증 정보를 임시 경로로 분리했다. 사용자 전역 plugin과 프로젝트 config, 자동 update/model fetch를 끄고 테스트용 Basic auth를 설정했다. 실제 OpenCode 서버의 health, SSE, status, permission, question, 존재하지 않는 native session의 404를 adapter로 확인했다. 모델 요청·실제 대화 생성·TUI route 검증은 실행하지 않았다. [원시 결과](data/2026-09-28-opencode-smoke.json).

초기 release 검사에서는 상속된 `LIBRARY_PATH`가 외부 `@rpath/libiconv.2.dylib`를 연결해 실행 전에 실패했다. Rust 빌드에서 이 환경변수를 제거하고 배포용 파일 복사 전에 `--version` 실행을 추가했다. 최종 binary는 시스템 `/usr/lib/libiconv.2.dylib`를 참조하며, 격리된 환경의 전체 검사에서 실행됐다.

## 추가 관찰 비용

최종 release binary로 source 하나에 1개와 50개 mock native session을 등록했다. 초기 동기화 후 각각 약 5초 동안 조회 없이 기다렸고 `ps`의 RSS·누적 CPU·thread 목록을 읽었다. provider fixture와 terminal child는 daemon RSS에 포함하지 않았다. core는 각각 1개 cat pane, 또는 cat pane 하나와 빈 pane 49개를 사용했다.

| 관찰 대상 | agentd RSS | agentd thread | SSE 연결 | idle 중 HTTP 재조회 | core RSS |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1 | 3.03 MiB | 1 | 1 | 0 | 4.11 MiB |
| 50 | 3.95 MiB | 1 | 1 | 0 | 4.36 MiB |

두 구간 모두 `ps`의 누적 CPU 차이는 표시 해상도에서 0.00초였다. 실제 CPU 사용이 절대 0이라는 뜻은 아니다. 초기 HTTP 요청 수는 SSE를 포함해 각각 6개·55개였다. 50개 native session이 source 하나를 공유하는 fixture이며, 50개 실제 AI 프로세스나 endpoint의 비용으로 일반화하지 않는다.

실행 파일 크기는 1,819,552 bytes다. [원시 측정](../benchmarks/data/2026-09-28-agentd-idle.json)에 binary SHA-256과 정확한 시간·byte 수를 남겼다. 실행 명령:

```sh
python3 tests/performance/agentd_probe.py --seconds 5 \
  --output .build/m3-agentd-probe.json
```

이 측정은 M3 첫 slice의 짧은 idle 관찰이다. 60초 이상 반복·burst/output·다중 source·지속 SSE 부하에서의 RSS/CPU/지연 budget은 아직 검증하지 않았다. [기존 Herdr/stock 비교](../benchmarks/2026-09-28.md)는 C core 비용의 이전 비교로 남기며, 이번 결과를 완성된 Herdr 관리 기능과 같은 범위의 비교라고 표현하지 않는다.

## 검토와 남은 범위

독립 코드 검토에서 발견한 비정규 pane ID, unknown 존재 여부, SSE에 의한 snapshot 지연, 대기/부분 event보다 이른 fresh 공개, 실패 응답의 dirty revision 무시 경로를 수정했다. 최종 코드 검토에 남은 차단 사항은 없으며 수정 뒤 통합·설치본·자원 측정을 다시 실행했다.

다음 구현 대상은 원래 TUI가 선택한 session을 증명하는 binding handshake와 attention UI다. provider 확대, durable prompt·승인·receipt·복구는 별도 단계다. 이번 commit으로 M3 전체나 제품 완료를 선언하지 않는다. Linux/BSD, 실제 모델 작업 중 장시간 관찰, real TUI route 전환, 네트워크/heartbeat 장시간 실패 행렬도 추가 검증이 필요하다.
