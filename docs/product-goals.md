# 제품의 최종 목표

상태: 제품 목표 초안. 사용자에게서 확정된 요구와 이 문서에서 구체화한 제안을 구분한다. 작성 기준은 2026-09-28이다.

## 제품 정의

masil은 tmux 사용자가 기존 키 조작·설정·스크립트·터미널 작업을 유지하면서 여러 코딩 에이전트를 운영하는 터미널 멀티플렉서다. 각 에이전트의 원래 TUI가 pane 안에서 작동하고, masil은 그 실행을 유지하며 상태·주의 요청·작업 연결을 공통 방식으로 보여 준다.

에이전트를 실행하지 않는 날에도 일반 터미널 멀티플렉서로 충분해야 한다. shell, editor, debugger, build, 로그 모니터링, SSH 작업도 같은 일급 기능이다.

## 확정된 요구

| ID | 요구 | 완료의 의미 |
| --- | --- | --- |
| P-01 | tmux의 모든 기능을 지원한다. | [호환 계약](tmux-compatibility.md)의 전체 범위를 충족한다. 기본 pane 기능만으로 완료 처리하지 않는다. |
| P-02 | 기본 키보드 설정은 tmux 기본값이다. | 키·키 테이블·repeat 동작·모드·환경에 따른 기본값까지 [키보드 계약](default-keybindings.md)을 따른다. `-f` 없이 시작하면 그 위에 [masil UI 레이어](mouse-ui.md)를 적용한다(2026-09-28 사용자 결정). 레이어는 옵션과 기본 바인딩이 없는 마우스 키만 쓰며 `-f`, 사용자 tmux 설정, 설정 화면이 끄거나 덮어쓴다. |
| P-03 | 에이전트의 원래 TUI를 감싼다. | 원래 composer, 도구 출력, 승인 화면, 단축키, 세션 선택을 그대로 사용할 수 있다. |
| P-04 | 터미널 관리와 에이전트 통합을 함께 제공한다. | Herdr 같은 실행 관리에 T3 Code 같은 provider 차이의 정규화를 추가한다. |
| P-05 | 최대한 빠르고 가볍게 동작하도록 설계한다. | 기본 terminal 경로를 추가 관리에서 분리하고, [성능 예산](design/performance.md)의 비용·지연·자원 gate를 실제 측정으로 검증한다. |

## 조사에서 보강한 품질 목표

[사용자 제공 Herdr 조사](research/herdr-feedback-2026-09-28.md)는 입력 전달·상태 판단·작업 복귀를 사용자가 다시 확인해야 하는 사례들을 제시한다. 보고서의 전체 사용자 비율이나 개별 이슈의 현재 상태를 검증한 것은 아니다. masil에는 이 사례들을 [신뢰성 계약 R-01~R-12](reliability.md)와 재현 조건을 가진 완료 기준으로 반영한다.

확인하지 못한 복사·prompt 수락·focus 이동을 성공으로 표시하지 않는다. 실패와 미확인을 구분하고, 부분 복구 결과와 재시도할 대상을 제공한다. 사용자가 로그 지연을 유실로 오해해 같은 요청을 다시 보내지 않도록 상태와 조회 방법을 함께 보여 준다.

이 요구는 초기 기능부터 적용한다. pane 수나 provider 수를 늘리기 전에 기본 입력과 상태의 의미가 맞아야 한다. 이미 존재하는 tmux 명령의 출력·exit status를 바꾸는 방식으로 적용하지 않는다.

## 완성된 사용 경험

아래는 확정된 방향을 구체화한 제품 목표다. 기능별 지원 조건은 숨기지 않고 표시한다.

### 익숙한 터미널 작업

사용자는 기본 `C-b` prefix로 session, window, pane을 조작한다. copy mode, buffer, 검색, status, mouse, popup, floating pane, 사용자 key table도 tmux 기준으로 동작한다. 기존 설정과 자동화는 기존 문법과 효과를 유지한다.

일반 shell pane을 agent pane으로 바꾸거나 반대로 돌아가도 터미널의 기본 동작이 달라지지 않는다. 새 에이전트 UI가 키를 가로채거나 기존 pane을 알리지 않고 축소하지 않는다.

한글·중국어·일본어 입력과 비영어 배열은 pane과 masil 자체 입력창 모두에서 검증한다. 출력 중 선택 유지와 실제 clipboard 목적지도 구분한다. 기존 editor와 가상 데스크톱 배치를 유지할 수 있어야 하며, masil 사용이 모든 작업 창을 한곳으로 옮기는 것을 전제하지 않는다.

### 여러 작업의 상태 파악

사용자는 여러 provider의 TUI를 동시에 띄우고, 지금 실행 중인 작업과 승인·답변·검토가 필요한 작업을 구분한다. 공통 목록에서 원래 pane으로 이동할 수 있다. 근거가 부족하거나 끊긴 상태는 `unknown`으로 표시한다.

프로세스가 살아 있음, 에이전트가 작업 중임, turn이 끝남, 사용자의 task가 끝남은 서로 다른 정보다. masil이 화면의 정지 상태를 작업 성공으로 바꾸지 않는다.

1~3개 작업에서도 필요한 attention과 복귀가 편리해야 한다. 동일 사용자가 다른 client로 이동해도 이미 확인한 사건과 새 사건을 구분한다. badge·목록·다음 미확인 작업 이동은 같은 확인 기준을 사용하며, client별 focus나 화면 배치와 구분한다.

### 작업과 실행의 연결

프로젝트와 checkout, pane, agent session, 사용자 task를 연결해 볼 수 있다. 이 추가 모델은 tmux의 session/window/pane ID와 의미를 바꾸지 않는다. 같은 디렉터리에서 작업하는 에이전트들을 구분하고, worktree를 사용하면 어느 작업이 어느 checkout에 속하는지 보인다.

worktree 준비에 파일 복사나 의존성 설치가 필요하면 사용자가 명시한 준비 절차와 실행 상태를 보여 준다. 준비·삭제의 진행·실패·재시도·취소를 다루며, 오래 걸리는 작업이 다른 pane 접근을 막지 않는다. 숨김 파일이나 인증 설정을 자동으로 전부 복사하지 않는다.

### 연결 해제 후 이어가기

client를 닫거나 네트워크가 끊겨도 살아 있는 server의 작업은 유지된다. 재접속하면 현재 화면과 현재 상태를 얻는다. server나 머신이 재시작되면 저장 상태와 native resume를 사용해 가능한 범위의 환경을 복원하고, 유지되지 않은 실행을 명확히 표시한다.

복구 목록에서 배치·cwd·프로세스·native 대화 연결의 결과를 대상별로 확인한다. 실패 항목만 다시 시도할 수 있고, 원래 대화 ref를 보존한다. 원격 인증이 필요하면 진행 경로를 안내하며, 사용자가 중지한 연결은 자동 reconnect가 다시 시작하지 않는다.

### 에이전트를 통한 자동화

사람과 에이전트는 명시한 pane 또는 agent session을 대상으로 관찰·입력·대기·취소를 요청할 수 있다. 승인 응답과 prompt 제출은 해당 provider가 제공하는 확실한 경로가 있을 때 공통 제어로 제공한다. 원래 TUI 조작은 계속 가능하다.

여러 작업의 순차 실행이나 결과 전달은 정확한 완료 조건과 사용자가 정한 대상에 따른다. 단순 무출력 시간이나 추정 idle을 근거로 다음 명령을 자동 실행하지 않는다.

## 기능을 추가하는 원칙

- 에이전트 기능을 꺼도 tmux 호환 기능은 완전해야 한다.
- tmux 기본 키를 에이전트 전용으로 바꾸지 않는다. 초기 에이전트 명령은 command prompt와 CLI에서 접근하고, 전용 키는 사용자가 설정한다.
- tmux 설정의 의미와 적용 결과를 유지한다. masil 추가 설정은 명확히 구분한다.
- provider 기능 차이는 capability로 드러낸다. 미지원 기능을 성공처럼 응답하지 않는다.
- 정규화한 상태와 그 원본 식별자·근거를 함께 보존한다.
- 관찰, 입력, 프로세스 종료, 파일 복원은 서로 다른 권한과 사용자 의도를 가진 동작이다.
- 성능은 tmux와 같은 작업 부하에서 비교한다. 에이전트 관찰 때문에 타이핑·화면·다른 pane의 반응이 밀려서는 안 된다.
- 성공 알림에는 그 결과를 확인한 근거가 있어야 한다. 외부 작업의 결과를 모를 때는 미확인 상태와 다음 확인 방법을 제공한다.
- 진단은 환경별 재현에 필요한 정보와 후속 정정을 남긴다. upstream 이슈가 닫혔다는 사실을 수정 배포나 masil 검증 통과로 바꾸지 않는다.

## 단계별 도달점

단계는 구현 순서다. 이후 단계의 tmux 기능을 최종 범위에서 제외하지 않는다.

| 단계 | 결과 | 통과 조건 |
| --- | --- | --- |
| D0 기준 확정 | 요구·용어·소스 기준·호환 목록 | 현재 문서 묶음과 기준 목록의 일관성 |
| D1 실행과 입력 | pinned tmux 기반 server/client, PTY, VT 화면, 기본 키와 최소 확장 | agent off 비용·실제 TUI·IME·modifier·resize·detach·복사 결과 검증. 이 단계는 tmux 대체품 완료가 아니다. |
| D2 tmux 전체 동작 검증 | 전체 명령·옵션·key table·mode·format·hook·control mode | fork와 확장으로 생긴 차이를 기능군마다 추적하고 수정 |
| D3 원래 agent TUI 통합 | 세션 식별, 관찰, attention, capability별 조작 | 같은 실행의 상태·전달 단계·다기기 확인·대상 종료 wait·unknown에서의 자동 입력 제한 검증 |
| D4 지속 작업과 다중 작업 | restore/resume, workspace/worktree, 제어 이력, 지원되는 checkpoint | 대상별 복구·원격 중지 의도·장시간 작업 격리, 중복 실행·잘못된 대상·파일/대화 불일치 검증 |
| D5 최종 목표 충족 | tmux 전체 호환 + 검증된 agent 통합 | [완료 판정](acceptance.md)의 전 영역을 통과 |

D2와 D3은 일부 병행할 수 있다. D3의 매력적인 기능이 D2의 미구현을 대신하지 않는다. 단계별로 새로 제공하는 기능의 신뢰성 시나리오도 통과해야 한다. 일정과 인력 추정은 이 문서에서 확정하지 않는다.

## 선택한 구현 방향과 남은 검증

사용자가 언어·스택 선택을 위임한 조건에서 [tmux C/libevent thin fork + Rust agentd](architecture.md)를 선택했다. terminal engine은 tmux 그대로이며, agentd는 별도 프로세스와 SQLite WAL/FULL을 사용한다. 새 명령은 `masil-agent`에 두고 기존 tmux 명령 축약·기본 키를 유지한다.

추가 목록은 요청 시 client-owned menu, 지속 overview는 선택적인 일반 pane으로 제공한다. opt-in status는 cache를 읽는다. `tmux` 호환 진입점도 선택적으로 활성화하며 system binary를 덮어쓰지 않는다. 세부 구현 순서는 [계획](design/implementation-plan.md)에 있다.

남은 항목은 provider별 실제 version/capability, platform별 runtime 지원, package 배치와 측정에 따른 budget 튜닝이다. 언어·엔진·저장 방식 전체가 미정인 상태는 아니다. 현재 수치 목표는 구현 결과로 검증해야 한다.

다른 GUI나 모바일 앱, 자체 LLM 실행 엔진은 현재 확정된 제품 목표가 아니다. 향후 논의가 tmux 전체 기능 지원을 지연시키거나 축소하는 근거가 되지 않는다.
